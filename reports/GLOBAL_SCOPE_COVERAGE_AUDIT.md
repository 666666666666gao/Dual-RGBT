## 2.25S 的几何证明

设 main 中心为 C。`regions.py:18-19` 的 broad 区域边长为 2S，单轴起点为 C−S。`policy.py:43-49` 的 8 个峰位置为：

`C − S + ((i + 0.5) / 8) × 2S = C + (2i − 7)S / 8`，其中 i=0…7。

因此峰中心范围为 C±7S/8。每个 LOCAL_EXTERNAL crop 边长为 S/2、半边长为 S/4；其单轴请求范围的并集为 `[C−9S/8, C+9S/8]`，总边长是 9S/4=2.25S。相邻峰间距为 S/4，小于请求边长 S/2，区间相接且重叠；二维 8×8 笛卡尔组合的 64 个方形确实填满这个方形并集。该并集是任意可能廉价峰的总范围，一次真实 action 只读取其中一个局部请求。

审计器另外按当前 float32 broad 和请求坐标算式枚举了每轴 8 个区间，逐序列所得 64 区域并集计数与 2.25S 统计完全一致：2,508 个中心越界、1,986 个零交集。双精度名义范围的分类计数也相同。这个检查没有恢复保存前的真实内部状态：原预测与 GT 以六位小数保存，几何重建仍是近似。

## 不能从覆盖数推出的结论

`policy.py:40-46` 的 LOCAL_MAIN 和 LOCAL_ALTERNATE 中心来自主 head 的 box/offset。`lib/models/layers/head.py:174-201` 对响应和宽高使用 sigmoid/clamp，但 offset 是未经 sigmoid 的原始输出；`cal_bbox` 以 `(cell+offset)/16` 解码中心。因此这两个请求没有 2.25S 的硬范围限制。

同样，`readout.py:37-58` 对最终局部框中心使用未经约束的 offset。宽高的 raw 输出受 query 源边长缩放的 sigmoid 范围限制，中心却可以在 query 外；后续 margin10 clip 是图像边界裁剪，不是 query 边界裁剪。宽高限制不能解释成整个预测框只能位于 ROI 内。

所以这份数据不是“所有动作的 performance upper bound”，也不能推出这些帧上的最佳动作 IoU 必为零或无法恢复。它没有保存/重算全部替代动作的输出，没有模拟选择不同动作后的新状态，也没有证明新训练模型会沿同一轨迹运行。中心在范围内不保证局部框完整覆盖目标，更不保证廉价峰定位、重型定位或恢复成功。

## 对下一源码方案的含义

该旧 dev 轨迹提供了具体证据：当前 2.0S 的 WIDE/cheap 来源和固定 8×8 external 峰即使取所有可能局部请求的并集，仍留有上述名义覆盖空缺。若下一设计要求廉价候选能在主状态偏离后检索任意图像内位置，当前有限区域不满足这个覆盖要求；全图廉价候选是有数据依据、值得单独验证的设计方向。

这不证明全图候选是唯一必要方案，不证明它会提高 PR/NPR/SR、速度或实际恢复率，也不支持把某个固定倍数当作已选最优阈值。本轮不建议无证据的 fallback，不要求改动正在运行的 source25，不撤销 R1 对原实现语义正确性的准入结论。新源码设计和它的真实贡献仍须分别审查与实测。

# C20 与 C882 的完整 dev 状态写入诊断

同一原 E0 架构、同一 cost=0.05、各自已完成的97条 dev／54646帧。排除97个初始化帧后，每组54549个跟踪帧，其中54289帧GT宽高为正。这里统计连续原始框 IoU 与历史关系，不重新报告 PR/NPR/SR；也不是当前冻结 cost=0 的完整 test 或新版 E1 的结果。

| 统计量 | C20 | C882 |
|---|---:|---:|
| 有效GT上的推断模板写入事件 | 6430 | 6584 |
| 其中 raw IoU<0.1 的写入事件 | 1053 | 1034 |
| 低IoU写入占有效写入比例 | 16.38% | 15.70% |
| 低IoU写入平均响应 | 0.8184 | 0.8050 |
| 低IoU写入时动作 STOP | 184 | 409 |
| 低IoU写入时已选择辅助查询 | 869 | 625 |
| 低IoU写入的上一帧已低IoU | 1044 | 1020 |
| 低IoU写入前已连续至少20帧低IoU | 851 | 809 |
| 全部有效跟踪帧中的低IoU帧数 | 12249 | 12445 |
| 包含推断写入的低IoU区段数 | 88 | 106 |
| 每非初始化帧记录的平均重型token | 549.221 | 529.672 |

1. C882 仍有1034次低IoU推断写入，占6584次有效GT写入的15.70%，对应平均响应0.8050。相对 C20 减少19次、比例下降0.67个百分点，尚不能据此认为更多 quality/gain 训练已经解决错误状态写入。
2. C882 的1034次低IoU写入中，1020次前一帧已低IoU，809次此前已连续至少20帧低IoU。写入通常伴随已有失败；这些轨迹没有模板回滚对照，不能证明写入造成后续漂移。
3. 409次低IoU写入发生在 STOP，625次发生在已选择辅助查询的帧。它支持继续研究最终结果与写入的验收；不能把625次直接解释为辅助查询的负收益，因为没有同状态主模态反事实框。

C882 的原始低IoU帧数增加196，而此前的同cost工具包SR略增；二者口径不同：本诊断按有效非初始化帧汇总连续IoU，原工具包按序列等权并沿用取整与特殊GT规则。保留两种原始记录，不改评分口径来消除差异。

## 可复现输入与边界

- 生产代码：[compare_dev_state_writes.py](../scripts/compare_dev_state_writes.py)，复用已有 CPU 几何与未来窗口函数。参数为 `--output`、`--events`、`--inventory`，输出路径须不存在。
- 完整数值及97条逐序列计数：[JSON](C20_C882_DEV_STATE_WRITE_COMPARISON.json)。私有输入清单封印595个输入文件，事件表包含两组全部低IoU写入；原始轨迹、GT和逐帧事件不上传仓库。
- 模板写入依据已执行 tracker 的 `frame%5==0 && confidence>=0.65` 规则推断，事件数不同于模态写入次数；STOP写一路，查询帧写两路。没有显式模板写入日志或模板回滚实验。
- GT宽高为正才进入原始几何统计。无效GT中断低IoU连续段；未来窗口只包含同序列后续完整有效帧，采用既有5／20／50帧范围。窗口重叠，不是独立试验。
- 两个已训练 checkpoint 各有一次 dev 轨迹，训练序列范围和更新数都不同；相同cost系数不保证相同实际计算量，token统计不证明真实加速。
- 本轮没有 NN 执行、SSH、GPU查询、测试配置修改或阈值调优。该诊断不会推迟正在运行的两个完整测试分片。后续仍按已登记 E0／E1 完整评价优先，再做查询验收／安全写入的实际控制实验。
- CPU 首次统计在最终JSON序列化时失败（NumPy整数类型），保留原失败代码、事件和输入清单；修正为Python整数后实际退出0。随后将生产器加入仓库并再次执行，数值、事件表与成功的私有运行完全一致。没有重启模型任务。

独立完整性审查另存 `C20_C882_DEV_STATE_WRITE_RESULT_AUDIT.md` 与 JSON；本文件的数值须连同审查的限定范围使用。

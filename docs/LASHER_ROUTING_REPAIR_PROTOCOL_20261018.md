# LasHeR 路由失败链诊断（2026-10-18）

## 已确认问题

E1 candidate C882 在 LasHeR test 上为 PR 67.612357 / NPR 62.545797 / SR 50.842354。固定轨迹统计显示：辅助查询率约 6.72%，TIR 主模态率约 52.16%；旧 E0 参考路径约为 83.93% 和 10.86%。因此当前最直接的失败链是：候选策略大量 STOP，同时主模态选择从 RGB 偏向 TIR。这个证据还不能把问题归因给单一头或单一模块。

## 本轮诊断

两条 dev 诊断均使用同一个 E1 C checkpoint `d4454775...31a362`，不改网络结构、模块连接或权重：

| Run | GPU | 运行时决策 | 目的 |
|---|---:|---|---|

| `diag_lasher_dev_auto_primary_20261018` | 1 | 主模态自动，强制 primary 局部查询 | 判断 STOP/gain 门控是否压制了必要辅助证据 |

两条路径只在 LasHeR dev97 上诊断，不能看 test 选参数。完成后使用同一 toolkit 重新评分 PR/NPR/SR，并记录辅助调用率、TIR率、平均/P95 延迟和模板更新事件。

## 决策门

- 若固定 RGB 明显改善：下一步优先做质量头的模态校准或 LasHeR 专用内部偏置，保持三模块和主干不变。
- 若强制 primary 明显改善：下一步优先重训 STOP/gain 头，使查询收益和实际定位改善一致；不直接把强制查询作为最终方法。
- 若两者都无改善：问题更可能在候选区域覆盖或局部读出执行器，停止继续调路由，先做执行器诊断。

所有诊断结果均属于 dev 证据；只有完成正式 policy repair、dev 冻结和三数据集 test 后，才能进入主结果表。


## 诊断结果

两条固定权重诊断都低于当前 E1 dev：

| 路径 | PR / NPR / SR | mean ms | 解释 |

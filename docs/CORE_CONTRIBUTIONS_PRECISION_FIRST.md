# Dual-RGBT 精度优先的三个核心模块

本文把当前实现、失败证据和待验证机制收敛到同一条决策链。文中“待验证”不表示已有精度收益。

## 1. 目标条件的主模态调度

输入是两路廉价预览、模板描述和历史状态；输出是对当前目标的 RGB/TIR 相对可用性。它解决的是“哪一路先完整编码”，不是整幅图亮度判断。

当前可验证基础是共享预览与 quality 头，Joint-Quality 训练加入同状态的相对质量监督。固定 RGB 的完整 dev 对照没有改善，因此不能把“RGB 永远为主”作为方案。完整训练结果出来前，不认领该模块收益。

## 2. 同状态定位收益驱动的区域请求

主模态定位后，候选请求在辅助重型编码前竞争 STOP。训练标签使用真实执行框相对主框的 IoU 差和请求 token 成本；Joint-GainPair 进一步比较同状态候选收益。

已有失败 E1 说明，减少辅助调用并不能保证精度；因此该模块的证据必须是相同候选池、相同预算下的完整 LasHeR dev 与 test，而不是 gain loss 或 oracle 候选覆盖。query evidence capture 已保存同帧主框和已执行请求收益，能区分“query低IoU”和“query比主框更差”。

## 3. 独立坐标的局部读出与安全状态更新

辅助原图 ROI 在独立坐标系中共享编码，local 使用 128 输入、8×8 读出，wide 使用 256 输入、16×16 读出；它允许查询主 crop 外区域。当前 tracker 选中 query 后直接替换 state，只有每5帧的 confidence 门控模板写入，尚无独立 query 接受门。

ATOM/PrDiMP 的官方开源实现（`visionml/pytracking` commit `7eb9e74bd3d40e29dbcec444902237da13de247b`）把分类定位标志、位置状态和分类记忆分开处理，IoU/密度分支用于框精修，不提供可直接迁移的跨模态统一阈值。基于这个真实问题，项目新增了未接入 tracker 的路线接受门和 dev-only 校准工具：分别按 RGB/TIR 与 primary/local128/wide 校准，接受定位和写入模板分开。必须在完整 LasHeR dev 上校准后重新闭环运行，才能判断 SR 是否改善。

## 贡献边界

- 共享编码、局部 ROI、模板阈值和常规拼接本身不单独计作新颖性。
- 三个模块只有在完整 LasHeR dev/test 对照中改善 PR/NPR/SR，且消融能拆出相对质量、同状态收益排序和安全接受的作用后，才可写成论文贡献。
- 当前目标为 LasHeR PR≥78、NPR≥72、SR≥62；严格的 baseline+6 目标仍另行保留。
- 当前32项训练、评估计划和活动权重不因本文档改变；FPS 暂不作为晋级条件。

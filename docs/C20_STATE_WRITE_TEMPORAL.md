# C20 完整 dev：错误写入前后的轨迹关联

范围是已完成的 C20 参考权重 `94be6239…`、cost0.05、97条dev序列/54646帧（54549个非初始化帧，54289个有效GT）。没有运行NN、更新模型或改动正在训练的46份源码。这不是全882 C、新版E1或完整test指标。

原始输入来自已封存预测、数据集GT和逐帧trace，逐文件SHA与既有M30诊断一致。事件按原tracker的frame%5==0且confidence≥0.65推断，事件数不等于模态写入次数。低IoU指原始连续框IoU＜0.1，较好定位指IoU≥0.5；均不是原工具包PR/NPR/SR。

## 观察、解释与下一步

1. 1044/1053次错误写入前一帧已经低IoU，851/1053次此前已连续低IoU至少20帧。因此，错误写入多数出现在既有漂移中。这使候选覆盖、身份判断和恢复查询继续成为首要问题；不能把模板门当作全部初始失败的解决办法。
2. 现有响应分数仍允许大量低IoU写入。但现有数据没有保留同一状态的主路径反事实、辅助查询后拒收结果或模板回滚轨迹，因此不能判断辅助是否造成损害，也不能证明错误模板使漂移延长。
3. 先完成E0/E1全C和三基准。其后做保持执行器、候选预算和训练量一致的控制：当前规则、关闭动态模板写入、相对初始模板质量门、查询证据验收与写入联合策略。分别观察失败进入、漂移持续和稳定恢复，再报告完整测试指标。现有部署参数保持冻结。

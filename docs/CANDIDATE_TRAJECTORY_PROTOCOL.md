# 候选收益策略的闭环刷新

2026-10-14：已实现独立的 `scripts/train_candidate_trajectory_policy.py`；本协议对应待绑定正式 B 终态的 C 草案。尚未执行 C 的 GPU 准入或完整训练，也没有新 dev/test/延迟结果。目标仍为 LasHeR PR≥78、NPR≥72、SR≥62，并降低完整系统实际推理成本。

## 当前证据与具体问题

B 使用 `EvidencePairs`：搜索区域从当前标注框扰动得到，模板从更早的标注框裁取，历史向量为零。部署的 `CandidateEvidenceTracker` 从上一帧预测框构造搜索区域，模板按预测更新，历史包含主模态、置信度、运动、尺度和距上次查询时间。因此训练与部署的输入分布确实不同；目前没有实验将这一区别认定为策略失效的唯一原因。

已有固定 train20 的真实查询实验说明，多候选区域里存在有价值的辅助证据，但强制查询也会损害定位。这支持检查学习策略能否选择有益动作，不能直接证明当前策略具有这种能力。先完成 B 的原生终态核验和选择诊断，再决定长 C 的执行。

## 本次实现

序列只从 frame0 标注初始化。后续每帧先保存真实的前一预测、模板和历史，再调用与部署相同的跟踪器推进状态。只有跟踪完成后，才读取当前训练标注生成标签。主搜索裁剪来自保存的前一预测，模板和历史来自实际轨迹；不以当前标注重置状态。

每五帧且标注有效时更新一次。四种查询家族按更新次数轮换：主候选局部、次候选局部、全图候选局部、全图候选扩大。每个主模态分别执行一个家族内均匀采样的辅助请求，生成两路主模态的实际 IoU 质量标签和两个实际查询的收益标签。收益保持 float32 的“查询后执行框 IoU − 主模态执行框 IoU”，允许负值。

另外重建本帧已经执行的选择，核对主模态、请求序号、家族、候选排名、候选数量及 token 成本。若已选查询与该主模态的采样查询相同，复用其执行结果；否则额外执行该已选请求，并把它加入收益监督。STOP 复用主模态输出。重放框必须与跟踪器实际返回框逐位相等，教师计算不得改变跟踪状态、模板或历史。

质量损失是两路主模态质量预测的 smooth-L1；收益损失平均所有本帧实际标注的查询，即两个采样请求及最多一个额外已选请求。该训练枚举预算与部署预算不同：部署每帧最多执行一个辅助请求。训练成本不能当成部署延迟。

共享执行器、定位读出与预览 CNN 保持 eval 和冻结；仅质量头、收益头八个 state tensors 更新，另 257 个保持逐位相同。独立序列化使用 `candidate_c` 阶段，不能复用 B 写入 `candidate_b` 的保存函数。

## 数据、初始化与准入

使用既定 882 个 train 序列顺序、seed2027、两轮、stride5。私有 manifest 重新计数得到 917106 次跟踪、182182 次更新、1764 次序列初始化。97-dev 用于配置选择，245-test 只用于冻结后的最终指标。baseline 72.74/69.16/57.84 按用户要求沿用，不重测精度。

C 的 M0 与正式训练都必须从完整 B 的 6250 更新权重初始化，不能从 B 或 C 的 sanity 权重初始化。先绑定正式 B checkpoint、COMPLETE、原生 exit0 状态和配置来源；再对最终 READY 计划进行独立源码审查。当前 `global_candidate_trajectory_draft_plan.json` 明确是 DRAFT，主入口会拒绝执行它。

真实 M0 计划执行首序列 20 帧、四次优化器更新，覆盖四家族和两路教师查询。检查有限非零梯度、正确 Adam 步数、257 冻结及八头变化、12 个预测字段严格重载相等，以及 K1 与旧四请求的几何和收益逐位一致。私有查询标签随后用数据集标注、实际图片尺寸和与执行一致的裁剪语义独立复算。

长 C 须等原完整训练/评估流水线终态且所需 GPU 释放后启动，避免其自动安排的双 GPU dev/test 被抢占。现有 B 的 37 个源码和原 GPU0 流水线不改。

## 与已有开源机制的关系

已核查的 [Where2comm Communication](https://github.com/MediaBrain-SJTU/Where2comm/blob/d3432523973b8c11df71e8e85750b2cb6fbe9dbb/opencood/models/comm_modules/where2comm.py) 的执行代码用空间置信图与阈值构造通信 mask；需求与提供者置信度的乘积只出现在这份文件的注释。可借鉴空间选择和预算记录，不能声称该路径已经实现接收方请求或定位收益监督。它先提取特征，不是辅助编码节省的证据。本方法的查询决定必须发生在重型辅助编码之前，并以实际执行定位收益训练。

已核查的 [KeepTrack 作者仓库](https://github.com/visionml/pytracking/tree/7eb9e74bd3d40e29dbcec444902237da13de247b) 提醒我们候选身份、置信度和模板管理需要分别检查。本次只补齐真实轨迹上的收益刷新和执行一致性，没有实现其身份关联，也不把其模板规则作为我们的贡献。

原始源码取得与核查记录见 `OPEN_SOURCE_REFERENCES.md`、`STATE_UPDATE_REFERENCES.md`。这些是机制借鉴，没有运行对应仓库作比较实验，也不据此宣称新颖性。

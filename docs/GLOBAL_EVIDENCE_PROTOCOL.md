## 三个连接的机制

1. 主模态调度仍使用两路 64 输入和首模板目标描述、历史状态，在完整主编码之前选择。
2. 共享微型 CNN 直接处理两路全图 256 预览，产生 32×32 匹配图；禁止 Preview.forward 隐式缩回 64。
   全图方形源包含原图；矩形图的填充位置不能成为候选。辅助候选在辅助 ViT 编码之前取得。
   保留原主候选和分离次候选，外加全图局部／全图宽查询，收益头预测实际执行框原图 IoU 差。
   不用“低置信必查询”代替请求收益；STOP 的增量收益和成本为零。
3. 选中后才从辅助原图读取局部像素，经共享完整深度编码和原图几何修正。
   三个局部动作输入 128（193 tokens）；全图宽动作输入 256（385 tokens）。
   全图候选局部源边长 S/2，宽查询边长 S，均以该候选为中心；S 来自当前主搜索。
   全图预览使用小 CNN，绝不把全图先送入 ViT 再选 token。

类 GlobalEvidencePolicy 继承已经准入的通用 gain/query 实现，只改全图预览及候选几何。
旧类、旧权重语义、旧计划与已运行任务完整保留。形状相同的参数严格加载，无自动兼容／fallback。
没有新增规模预测头；当前先测候选覆盖及实际收益，尺寸细节由实验支持后再改。

## 训练与准入

初始执行器是已完成 evidence_formal_a 的真实正式权重 d1981fef9efe797e14627515fe3b8e49c235efbe1d548a25a1af7a8c8412ca07。
模型由原 B 严格构建后严格加载此权重，全部新 A 均明确继承；诊断权重不进入正式 A。
sanity A：80 对／10 更新，RGB/TIR×5 动作各8；B：16 对／2更新；C：真实10帧／2更新。
必须核验梯度、优化器、冻结张量与保存后完整 forward strict 重载逐位一致，再开始正式训练。
A：5×10000 对，6250 更新，平衡训练执行路径。全图局部和宽查询各半训练批可使用 GT 附近教师区域，
其余使用当前廉价候选；教师只用于 A，不进入在线执行、B 反事实或 C 状态。
B：固定执行器，训练共享预览和 quality/gain，5×10000 对；实际执行 margin10/float32 框生成 IoU 差标签。
C：冻结执行器／预览，完整 882 序列×2 轮 own-state 闭环，每五帧监督 quality/gain。
只首帧用 GT 初始化；所选反事实必须逐位重现实际执行框，未读取辅助时不更新辅助模板。
不使用 dev/test 标签训练；dev 校准预算，test245 完整报告 PR/NPR/SR。

前置机会诊断必须检查充分训练后的主模态和局部／宽辅助的实际收益分布。
若 oracle 局部查询没有收益，应先修执行器／候选，不靠继续训练门控掩盖问题。
全图微型 CNN 的额外开销与端到端均值／P95必须计入，token 数下降不等于实际提速。
不得由 SOURCE_PASS 或 M0 推断精度、效率或三个独立有效创新。

## 开源借鉴与差异

[AdaFocus V2 作者仓库](https://github.com/LeapLabTHU/AdaFocusV2)研究视频分类的区域选择，
提供插值取 patch 的端到端空间动态网络；原实现不是 RGB-T 跟踪的定位收益或在线恢复证据。
本实验只借鉴重型编码之前选择原图区域的执行原则；没有复制代码、加载其模型或宣称该原则新颖。
[KeepTrack 作者仓库](https://github.com/visionml/pytracking)处理干扰目标的跨帧候选身份关联。
其候选关联提醒我们不能把强响应直接当真目标；本版先保留明确次候选和以真实定位收益决定是否读取，
未实现或借用其匹配网络，不能宣称已解决身份保持。
目标差异在定位收益与空间请求的连接，需同预算周期／置信度／固定区域对照证明。

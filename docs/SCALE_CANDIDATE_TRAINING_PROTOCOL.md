# 双间距候选控制器的训练与重载准备

这是SCALE_CANDIDATE_PROTOCOL.md中的训练入口补充，不改变正式E0/E1队列；不代表新NN已经通过或新指标已经产生。当前只准备 B，后续 C 与正式评估尚未接入。全局候选两类间距0.25/0.50不是已选出的数据集最优参数。

新增 train_scale_candidate_policy.py，直接使用新策略，复用已有数据分布、空间执行器、quality/gain监督和因果执行检查。没有动态替换旧模块全局变量、修改旧工厂或让旧E1评估误接收新权重。仅8个quality/gain状态张量更新，257个执行器/预览状态冻结；同一初始CADTrack去三模块/SOT来源，重新从原拟合预览ad059943开始，原权重不动。

每个batch轮换四种查询家族；对两种主模态各从实际存在的家族请求均匀抽一个，真实执行后计算原图裁剪框IoU及signed差。新候选的监督重新产生，不复用旧候选label。日志分别记录单家族可选请求数、两类去重位置总数、格点和家族内rank，避免将至多15个不同位置误称为单类8候选。当前 B 仍是GT-jitter离线成对状态，不能当作真实闭环C。

checkpoint和config.json保存candidate_config中的local_radius_fraction、wide_radius_fraction、max_candidates。load_scale_candidate_checkpoint从已保存配置恢复几何参数，再严格加载全部模型状态；没有默认半径或旧格式fallback。M0对比14个输出，包含两种计数与请求格点，验证配置恢复、严格重载、K=1旧四请求、实际梯度/Adam更新、冻结状态，以及10帧真实因果执行重放。

计划 M0 为32个真实训练样本、4次更新、64个新query标签，M0权重不作正式训练起点。正式 B 为5×10000样本、batch8、6250更新、100000查询标签，来源覆盖全部882条训练序列；正式运行必须读取此计划实际M0 COMPLETE/native exit0与重载通过记录。两种实验都必须先通过独立SOURCE复核，不会由本文件或计划自动启动。

现有E1的0.25/0.25完整版本作为统一参数参照，原模型不改。仅在未来独立验证中比较配置；三基准测试不用于选择间距。当前没有数据集专用已训练版本。完整 C882、dev冻结、LasHeR/RGBT210/RGBT234和完整系统计时需要专门的新版本配置，不能套用旧E1的正式收据。

GPU执行等待现有完整训练、三基准队列优先完成，仍每卡单个正式任务。长B估时先参考已完成B记录，首节点10分钟校正吞吐，之后临近预计结束才检查，必要复查240秒。M0先180秒，必要240秒。无NN运行前不填写实际损失、通过结果、用量或成绩。

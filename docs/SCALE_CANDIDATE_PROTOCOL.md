# 按请求尺度设置候选分离参数

依据已复核的 CANDIDATE_RETRIEVAL_LIMITS.md：同为8候选时，统一增大分离半径对 local/wide 的覆盖影响不同。这里实现模块二的内部参数对照，保留总体架构、三个模块职责、955维收益头及共享执行器，不增加学习参数。它不是独立新颖性或已经成立的精度改进。

## 已实现的执行路径

新增 ScaleCandidateEvidencePolicy，继承现有候选策略的收益、成本与局部执行方法，只替换候选几何生成。local/wide 分别在同一已有辅助预览响应图上做贪心空间排除，半径分别为主搜索ROI边长S的指定比例。选择发生在重型辅助编码之前。主候选与主次候选、ROI尺寸、原始像素读取、STOP以及至多一次辅助执行均保持现有语义。

- 普通对照：local_radius_fraction=0.25，wide_radius_fraction=0.25，逐位恢复原公共候选池。
- 按尺度对照：local_radius_fraction=0.25，wide_radius_fraction=0.50。它只是待训练、待验证配置，不是为某个测试集选出的最优值。
- 每类最多8个全图请求，另有两个主搜索请求，故仍最多18请求加STOP。两类合计可能读取至多16个不同的廉价预览位置，不能继续称为公共8点池；候选生成及收益打分的额外时间必须实测。

请求仍按rank交错local/wide，每个rank是其自身家族中的序号。新增 request_cell_indices 记录每个请求对应的全图格点；family_candidate_counts 记录两个真实列表长度；candidate_indices 是两个列表的去重并集。原tracker的 candidate_count 因而表示不同格点总数，不能在新结果中解释成任一单类候选数。新配置、计数与监督不能伪装成旧 E1 的正式收据。

## 准备验证与后续顺序

CPU 几何检查使用封存的1752份辅助响应图和真实搜索几何、图像尺寸；主预测张量是明确标记的人工几何输入。实际调用原策略及新策略的方法，与独立NumPy排除扫描比较。验证公共半径下四个原输出逐位一致、K=1旧四请求一致、不同家族的坐标/排序/计数/ROI尺寸及请求数上限。它不构建神经模型，不加载权重、不执行NN，不是GPU准入或跟踪指标。

新模型未接入任何正在运行的训练、控制器或正式评估工厂。原64份源码与计划不改。先完成独立源码复核；正式GPU验证等待现有 E0/E1 完整训练和三基准评估的优先任务结束，不新增抢占任务。

之后才进行真实数据前向、反向、优化器更新、冻结张量及严格重载检查，并刷新新候选分布对应的收益监督；M0权重不能作正式训练初始化。沿用 CADTrack 去三模块、SOT 来源，初始化文件不变。新池不能仅靠旧策略权重、旧label或覆盖oracle宣称有效。完整闭环训练、LasHeR 97 dev 选型和三基准正式成绩仍需完成；RGBT210/234专用内部配置须先登记独立验证协议。最终比较应匹配实际请求数、token预算并报告整机平均/P95耗时。

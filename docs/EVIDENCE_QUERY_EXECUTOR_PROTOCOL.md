## 可执行的计算路径

1. 上游根据当前已获得的信息选择区域，先从辅助原图裁剪，再调用reader。不能先重型编码全辅助图。
2. 每路查询包含两张128模板：129模板/CLS tokens。局部输入128只投影64搜索patch，
   经过同一完整深度的共享backbone，总193tokens。较宽256输入总385tokens。
3. 局部搜索使用原16×16位置嵌入的中央8×8，保留64个独立位置，不是池化后丢失空间位置。
4. 缓存的主模态16×16特征按真实源图坐标投影到查询8×8或16×16。
   查询不受原main网格索引范围限制；主路径无覆盖的位置是0特征，辅助像素来自独立源区域。
5. 共享decode/head直接在查询网格上做空间修正，局部8×8不重建成旧16×16。
   CENTER框使用实际网格边长解码，不修改原head.feat_sz，也不改原全量tracker的代码。
6. 查询相对cxcywh通过独立的[源left,top,side]映射到原图xywh。
   在线调用者最后按原clip_box margin10执行一次；它尚未实现，不能称已有正式在线结果。

source side 和重型输入大小独立：请求范围变大并不自动增大输入tokens；
固定128输出也可以从原图另一位置取区域，但候选选择、像素密度及定位有效性必须重新训练验证。
8×8卷积计算区域较小是执行形状，不能在尚未测量时换算成实际整机提速。

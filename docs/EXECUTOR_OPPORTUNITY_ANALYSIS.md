# A7 的逐样本查询机会

2026-10-13，对已保存的 `dev_samples_epoch07.csv` 做CPU分析，无新增模型前向或训练。
数据是70条dev序列的100个GT周围裁剪，每样本两模态×五动作，1000条配对记录。
脚本核对了所有(sample_id, modality, action)组合、序列名和帧号。
下表是同一A7执行器的裁剪IoU与损失比较，不是完整跟踪PR/NPR/SR。

| 执行或诊断 | 平均裁剪IoU | IoU≥0.5样本数 | 平均重型token数 |
|---|---:|---:|---:|
| 固定RGB，STOP | 0.707919 | 85/100 | 385 |
| 固定TIR，STOP | 0.615159 | 71/100 | 385 |
| 固定RGB，PRIMARY局部辅助 | 0.723524 | 86/100 | 578 |
| 固定TIR，PRIMARY局部辅助 | 0.705281 | 85/100 | 578 |
| 固定RGB，EXPAND完整辅助 | 0.719969 | 87/100 | 770 |
| 固定TIR，EXPAND完整辅助 | 0.719970 | 87/100 | 770 |
| GT诊断：按单模态损失选主模态，STOP | 0.761594 | 89/100 | 385 |
| GT诊断：选主模态后选最佳动作 | 0.779614 | 91/100 | 529.55 |
| GT诊断：全部十条路径中选最低损失 | 0.788746 | 92/100 | 520.01 |

1. 主模态存在逐样本变化。虽然RGB单独的平均表现较好，单模态GT诊断仍选择
   60个RGB和40个TIR。该诊断支持检验廉价调度是否可以学习这种变化；
   它不能证明当前正在训练的调度器已经实现这项增益。
2. 已经较好的定位仍会被辅助损害。PRIMARY在主IoU≥0.8的RGB53个样本中
   有30个负收益，平均signed损失收益−0.013514；TIR34个样本中有13个负收益，
   平均−0.058551。主IoU低于0.5时收益均值为+0.284407/+0.919056，
   但RGB仍6/15、TIR仍4/29无益或有害。两者提示请求价值应单独学习。
3. 覆盖不等于改善。PRIMARY覆盖GT≥90%的RGB80个样本仍有38个负收益，
   TIR76个样本仍有18个负收益。这个数据不能支持只用区域覆盖率判断是否请求。
4. 主模态选择与查询价值需要连起来检验。先按单模态损失选主模态，再选动作的
   GT诊断选择45次STOP、35次局部、20次EXPAND；联合选择路径时分别39/52/9。
   联合诊断平均IoU比前者高0.009132。它说明单模态最合适的一路，
   未必也是获得辅助之后最合适的起点；当前系统仍采用先预测单模态质量的简单方案。
5. 局部辅助与完整辅助各有优劣。RGB PRIMARY相对EXPAND平均IoU+0.003556，
   47个样本更好、47个更差；TIR PRIMARY平均−0.014689，51个更好、45个更差。
   不能从均值推断所有样本或两种主模态都适合相同查询预算。

上述GT策略用定位损失选择，选择后报告IoU；并不是直接最大化IoU。
GT只用于这份离线诊断，不进入可部署策略、dev预算规则或test执行。
token是执行工作量代理，不是FLOPs、真实延迟或参数量；这些诊断不能作为
完整跟踪轨迹上界。样本不是独立序列，100个裁剪不支持正式显著性或稳定提升声明。
现有CSV也没有模型响应置信度，不能把“主IoU高”写成“模型很自信”。
